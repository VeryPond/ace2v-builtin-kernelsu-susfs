# 与既有 CVE 的对比

本仓库发现的 MTK 证书校验缺陷，与设备上已存在的两条 preloader CVE
是**不同**的问题。三者关系如下。

## 设备上的既有 CVE（离线扫描结论）

| CVE | CVSS 3.1 | 组件 | 本机状态 | 依据 |
|---|---|---|---|---|
| CVE-2025-20730 | 6.7 | preloader | **存在漏洞（未修补）** | MT6983 在厂商受影响列表；两个 preloader 槽均为 2023 年构建，早于 2025-11 修复 `ALPS10068463` |
| CVE-2023-20696 | 6.7 | preloader | **不在影响范围** | MT6983 不在该公告的受影响芯片列表（补丁覆盖 MT6880/MT6890 等 24 款，不含 MT6983） |

两条 CVE 的利用前提均为**攻击者已持有 System 权限**，属本地提权类。

## 本仓库的缺陷

| 维度 | 两条 CVE | 本缺陷 |
|---|---|---|
| 类型 | 本地提权 | **引导链签名校验绕过** |
| 前置条件 | 已持有 System 权限 | **物理接触 + 可写分区** |
| 是否需私钥 | 否 | **否** |
| 影响 | 提权 | **绕过可信启动，取得引导链控制权** |

前置条件更低，影响面更高。

## 与上游工具的关系

`pwnage24mtk` 工具 README 自述针对 CVE-2023-20696，
并标注 "Patched"。但在本机固件上：

- 工具描述的缺陷形态**可以复现**（模型内 VALID）
- 真机差分实验**证实 legacy 形态生效**（`docs/LK_EXPLOIT_VERIFY.md`）
- 固件 preloader 停留在 2023-02/03 版本，**未随系统分区同步更新**
  （系统分区已到 2026-02）

## 处置建议

- 保持 efuse 安全启动链路（`sbc_en` / `daa_en` / `sla_en` / `jtag_dis`）开启
- 向 MTK / OPLUS 反馈该解析逻辑缺陷，确认 MT6983 preloader 的修复状态
- 实验结束后用原始 `lk_a.img` 刷回，恢复出厂校验状态
